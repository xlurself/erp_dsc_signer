# F1 — Specification: dialogs in a child process; PIN never stored, logged or sent

## 1. Scope, evidence, what changes
Fixes the macOS failure where `tk.Tk()` on a non-main thread aborts the process (reproduced: exit -6, `NSException`; uv Tk 9.0 Python and /usr/bin/python3; Homebrew Pythons lack `_tkinter`) and makes the owner rule enforceable: the DSC PIN is never stored, logged or sent by this tool or the ERP site.

**Out of scope (declared):** tokens that hide their certificates until login. Today `token.py:57-64` raises `PinRequired` for them, the Desk stops at `sales_invoice.js:89-91`, so the "continue to signing" text in `errors.py:47` is already untrue. F1 does NOT build that flow. `PinRequired` is replaced by `CertificatesHidden` (code `TOKEN_CERTIFICATES_HIDDEN`, 409, NO `details`), raised ONLY when a session opened and `findObjects` returned `[]` without error: "This token hides its certificates until login, which this version of the signer does not support." Any other zero-certificate outcome (session open failure, `findObjects`/parse error, certificates without `CKA_ID`) is `TokenUnavailable` with the existing pre-login text. The empty-PIN check at `token.py:70-71` is deleted (an empty PIN cannot reach it under §6). The test at `test_token_errors.py:46` is renamed and its fixture changed to a session that opens and returns no objects.

Evidence (checked against code): only `tk.Tk()` site `ui.py:98`; `pin.py:56-57` swallows the cause; ERP side has no PIN parameter (`api/signing.py`, `sales_invoice.js:65-77`); `service.py:223-226`+`config.py:36,92` accept `body["pin"]`; `token.py:100-117` iterates slots with a token and logs in on the first one it opens (a failed login aborts the loop; it moves on only after a successful login on a slot that lacks the key) and ignores the selected certificate's `token_serial`; `service.py:221` builds `TokenClient` before `ask_for_pin`; a consent Deny is persisted 24 h (`trust.py:42`, `service.py:93-95`); `origins.py` filters no characters; `pairing.py:160-161` and `pin.py:27` silently truncate claims; `signer.log` already holds a daemon traceback; `local_signer/` has no `subprocess`.

Files changed: NEW `dialog_child.py`; `ui.py`, `pin.py`, `pairing.py`, `token.py`, `service.py`, `errors.py`, `config.py`, `cli.py`, and `erp_dsc_signer/public/js/sales_invoice.js` (freeze text). Deleted: `UiTimedOut`, `UiUnavailable`, `PromptTimedOut`, `HARD_TIMEOUT_SECONDS`, the executor, `new_tk_root`, `PIN_TIMEOUT_SECONDS` (`pin.py:15`), `DIALOG_TIMEOUT_SECONDS` (`pairing.py:40`), `MAX_DOCUMENT_NAME`, `SignerService.serve_forever`, `PairInProgress` (only `service.py:86,113` raise it; replaced by `DialogBusy`), `PinRequired`. Kept: `UiBusy`.
Existing tests changed: `test_cross_process_and_ui.py` (all `UiTimedOut` and `hard_timeout=` uses; the executor/hard-timeout tests are DELETED and replaced by `tests/test_dialog_host.py`; `test_dialog_exception_releases_the_mutex` is kept for ordinary exceptions; `DialogHost.busy` stays in the API); `test_service_http.py` (exact lines resolved at build; the affected tests are: the `UiUnavailable` import; `_FakeDialogHost` and every `dialogs.calls` use; `test_concurrent_prompt_is_429`; the injected consent/PIN fakes in `setUp`; the server construction; the 503/`--allow` test). Rules: tests that expect the dialog path set `service.consent = consent_dialog` and `service.pin_prompt = request_pin` (the REAL ones) with a stub-child host; the "never reached" tests assert the fake's call list is empty; the busy and 503 tests use the real functions so a stub child actually runs; the server comes from `make_server(address=None)` (port 0 in tests, never the production port 17777); `test_pairing.py::TestConsentText` (text now built from separate fields; exact lines resolved at build); `test_token_errors.py` (:46 rename). Public signatures: `request_pin(origin, document_name, *, host, warnings=(), final_try=False)` and `consent_dialog(origin, claims, *, host)`; `host` is REQUIRED (one shared host, one lock).

## 2. Constants (each defined exactly once)
`dialog_child.py` (the leaf; `ui.py` imports from it): `MIN_DIALOG_SECONDS=5`, `MAX_DIALOG_SECONDS=300`, `DEFAULT_DIALOG_SECONDS=120`, `INPUT_GUARD_SECONDS=1.5`, `MAX_REQUEST_BYTES=8192`, `MAX_REPLY_BYTES=4096`, `MAX_ORIGIN_CHARS=120`, `MAX_CLAIM_CHARS=140`.
`ui.py`: `STARTUP_ALLOWANCE_SECONDS=10`, `GRACE_SECONDS=2`, `KILL_DELAY_SECONDS=2`.
`service.py`: `MAX_PIN_FAILURES=3`, `PIN_LOCKOUT_SECONDS=900`, `TOKEN_LOCK_TIMEOUT_SECONDS=20`.
The timeout is a code constant chosen by the signer; it is never read from the HTTP body. The parent clamps it to `[MIN,MAX]`, sends the clamped value, and the deadline is `STARTUP_ALLOWANCE + clamped + GRACE` from spawn. The child's own timer starts when its window maps. Tests may patch constants.

## 3. Components
1. `dialog_child.py` (NEW, LEAF). Module level = stdlib imports, constants and `def`s only; no import-time stdin or Tk. `main()` order: `setrlimit(RLIMIT_CORE,(0,0))` (POSIX; guarded import) → read ONE line with `sys.stdin.buffer.readline()` (returns at the `\n`; stdin stays open) and validate it → THEN start `watch_eof()` (a daemon thread that reads and discards stdin until EOF, then exits the process silently if the reply is not yet written; it starts after the request is consumed so the two never compete for stdin) → lazy `import tkinter` → dialog → destroy window → write one reply line + flush → `os._exit(0)`. Exit code 65 = invalid request (re-validated in the child). Importable helpers: `decide(event)`, `consent_layout()`, `build_consent_window(layout, ...)` (takes the layout as a parameter), `watch_eof()`, `validate_request()`. MUST NOT import `ui`, `pin`, `pairing`, `service`, `token`. Only file allowed to import `tkinter`/`_tkinter` (G1).
2. `ui.py` — `DialogHost`: ONE acquisition point `run_exclusive(fn)` (non-blocking, raises `UiBusy`, not re-entrant). `run_dialog(request) -> dict` validates, then `run_exclusive(self._supervise)`; it never takes the lock itself. Returns a validated reply dict or raises `DialogFailed(cause)` (`DialogFailed` derives from `Exception`). `child_command(script=None)` is a PURE function returning the argv; `DialogHost(child_script=None)` overrides only the script path. `shutdown()` sets the shutdown flag (lives here) and calls `kill_child()`, which kills the tracked child without the lock.
3. `pin.py` / `pairing.py` — build the request (separate `origin`, `claims`, `warnings`, `final_try`), call `host.run_dialog`, map per §6; `UiBusy` → `DialogBusy`. `document_name` becomes a claim. The silent `[:120]`/`[:MAX_DOCUMENT_NAME]` slices are deleted; the SAME replacement rule (over-long or unreadable claim → visible placeholder) is applied to `SiteClaims` inside `verify_pairing_proof`, so `trust.allow`, the `/v1/pair` response and `erp-dsc-local --list-origins` never receive raw site text (closes terminal-escape injection); the CLI additionally strips Cc/Cf characters when printing. ## 4. Spawn contract
- `[sys.executable, "-I", <abs path of dialog_child.py>]`, `shell=False`. Never PATH `python`; no caller data on argv. The file must be a real file (not zipimported).
- `stdin=PIPE, stdout=PIPE, stderr=DEVNULL, close_fds=True`; POSIX `start_new_session=True`; Windows `creationflags=CREATE_NO_WINDOW`; best-effort Job Object `KILL_ON_JOB_CLOSE` via `ctypes` assigned immediately after `Popen` (a short unassigned window exists; no Windows CI here, so this part is manual-verification only).
- cwd = `tempfile.gettempdir()`. env allowlist: `PATH`, `HOME`, `TMPDIR`, `LANG`, `LC_*`, copy-if-present `DISPLAY`, `WAYLAND_DISPLAY`, `XAUTHORITY`; Windows adds `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`, `USERPROFILE`. `TCL_LIBRARY`/`TK_LIBRARY`/`TCLLIBPATH` are NOT forwarded. The child asserts `sys.flags.ignore_environment == 1`.
- No `preexec_fn`. stdin stays open as a lifeline; the parent closes it only when done.
- The request is `json.dumps(..., ensure_ascii=False).encode("utf-8") + b"\n"` (exactly ONE trailing newline; the JSON itself contains no raw newline), ≤ `MAX_REQUEST_BYTES` INCLUDING the newline, and is written and the reply read on helper threads under the ONE monotonic deadline. Swallow `BrokenPipeError` and `OSError` with `errno==EINVAL` (Windows closed pipe) on write. The reader reads at most `MAX_REPLY_BYTES+1`; the extra byte or a second line makes the parent kill the child and record kill-reason `oversize`.

## 5. Lifecycle and shutdown
One child at a time, tracked. After a complete valid reply line, the parent waits at most `GRACE_SECONDS` for the child to exit, then kills it and ACCEPTS the reply (the PIN is not held for the full deadline). The kill reason is set-once (first recorded wins) and `deadline` is recorded only if `poll() is None`. On deadline/shutdown/oversize: record the kill reason, `terminate()`, `kill()` after `KILL_DELAY_SECONDS`, `wait(timeout=KILL_DELAY_SECONDS)`. If the child still cannot be reaped, the lock is NOT released (one child at a time stays true): `DialogHost` sets `_wedged`, one fixed log line is written, and every further dialog request raises `DialogWedged` (`DIALOG_WEDGED`, 503, "The signer's dialog process could not be stopped. Restart the signer."); `run_exclusive` checks `_wedged` first. Ordinary exceptions still release the lock (`test_dialog_exception_releases_the_mutex`).
Signals (`cli.main`): SIGTERM and SIGINT, and SIGHUP only if `hasattr(signal,"SIGHUP")`. The handler only sets the flag on `DialogHost`, calls `kill_child()` without the lock, and runs `server.shutdown()` on a NEW thread (never on the `serve_forever` thread). Helper threads are daemon threads. Test stubs die by `SIGKILL`, never `os.abort()`.

## 6. Wire schema and the ERROR TABLE (the ONE authority)
Request (stdin, one line): `{"v":1,"kind":"pin"|"consent","origin":str,"claims":[str],"warnings":[str],"final_try":bool,"timeout":int}` (`type(x) is int/bool/str`). `origin`, `claims` (site-supplied, untrusted) and `warnings` (the signer's own) are separate fields. Parent validation before spawn (failure, including any `UnicodeEncodeError`, → `DialogFailed("dialog_request_invalid")`, no spawn): `v==1`; request ≤ `MAX_REQUEST_BYTES`; `origin` ≤ `MAX_ORIGIN_CHARS` with no character of Unicode category Cc, Cf, Cs, Co, Cn, Zl or Zp (never truncated or altered); a claim over `MAX_CLAIM_CHARS` → "(claim too long)"; a claim containing any Cc/Cf/Cs/Co/Cn/Zl/Zp character, any Zs other than U+0020, or one of the invisible fillers {U+3164, U+115F, U+1160, U+FFA0, U+2800, U+034F, U+180E, U+17B4, U+17B5, U+16FE4, U+1D159} → "(unreadable claim removed)"; U+00A0 is first mapped to an ordinary space; runs of spaces are collapsed and a claim that becomes empty is unreadable; combining marks Mn/Mc stay allowed (Indian-script names need them) and ZWJ U+200D / ZWNJ U+200C are allowed ONLY next to a virama (canonical combining class 9; ZWJ may also directly precede a virama, as in Bengali ya-phala), every other Cf stays unreadable; the cleaning is idempotent. The http-downgrade notice (`pairing.py:176-180`) is a `warning`.
Reply (one line): `{"v":1,"kind":K,"result":R[,"value":V][,"cause":C]}`; allowed: pin `entered`(+non-empty `value`) | `cancelled` | `timeout`; consent `allow` | `deny` | `timeout`; either kind `unavailable`(+`cause` in {`tk_import_failed`,`tk_init_failed`}). The child maps an empty PIN to `cancelled`.
Classifier — ORDERED, by recorded kill reason, not by the clock; first match wins:
1. daemon shutting down → `dialog_shutdown`
2. kill reason `deadline` → `dialog_timeout`
2b. kill reason `oversize` → `dialog_bad_reply`
3. `Popen` raised → `dialog_spawn_failed`
4. exit 65 → `dialog_request_invalid`; exit < 0 → `dialog_process_crashed`; exit > 0 → `dialog_process_failed` (stdout ignored; Windows has no negative codes)
5. exit 0 and ANY of: empty / non-JSON / missing key / extra key / extra line / `v != 1` / kind mismatch / unknown result / unknown cause / `value` present on a non-`entered` result / `cause` present on a non-`unavailable` result / `entered` with empty `value` → `dialog_bad_reply`
6. valid reply → per table.
Replies are parsed by a helper that RETURNS a sentinel and raises outside any `except`, so no exception object holds the reply text.

| Outcome | PIN path (`/v1/sign`) | Consent path (`/v1/pair`) |
|---|---|---|
| `cancelled` | `PinCancelled` | — |
| consent `deny` (Deny click, Escape, close) | — | Deny; denial + cooldown recorded |
| `timeout` result | `PinPromptUnavailable(dialog_timeout)` | `PairPromptUnavailable(dialog_timeout)`; NO denial recorded |
| `unavailable` + cause | `PinPromptUnavailable(cause)` | `PairPromptUnavailable(cause)` |
| classifier 1-5 | `PinPromptUnavailable(cause)` | `PairPromptUnavailable(cause)` — never Deny, never consent, no denial/cooldown, no trust write |
| another dialog on screen (`UiBusy`) | `DialogBusy` | `DialogBusy` |
| signer wedged (un-reapable child, §5) | `DialogWedged` | `DialogWedged` |
Closed causes (9): `tk_import_failed`, `tk_init_failed`, `dialog_spawn_failed`, `dialog_process_crashed`, `dialog_process_failed`, `dialog_bad_reply`, `dialog_timeout`, `dialog_shutdown`, `dialog_request_invalid`. The two `*PromptUnavailable` classes raise `ValueError` on any other cause (always). They emit `error.message` = the sentence below and `error.details={"cause":cause}`; the Desk shows only `message`, so the cause is in the sentence. The pair-path message appends " Or pair from a terminal: erp-dsc-local --allow <origin>".
Messages: `tk_import_failed` "The signer cannot show a dialog because Tk is not available in its Python (tk_import_failed)." · `tk_init_failed` "The signer could not open a window on this desktop (tk_init_failed). Run it in a logged-in desktop session." · `dialog_spawn_failed` "The signer could not start its dialog process (dialog_spawn_failed)." · `dialog_process_crashed` "The signer's dialog process crashed (dialog_process_crashed)." · `dialog_process_failed` "The signer's dialog process exited without an answer (dialog_process_failed)." · `dialog_bad_reply` "The signer's dialog process returned an unexpected reply and was ignored (dialog_bad_reply)." · `dialog_timeout` "No answer was given in time and the dialog was closed (dialog_timeout)." · `dialog_shutdown` "The signer is shutting down (dialog_shutdown). Try again." · `dialog_request_invalid` "The signer refused to show a dialog for an invalid request (dialog_request_invalid)." · `DialogBusy` "Another signer dialog is already waiting for an answer on this computer."

## 7. Token handling and `/v1/sign` order
Order (before any PIN is typed): resolve provider → `TokenClient` → `certificates()` and select the certificate (hidden-certificate tokens stop here with `CertificatesHidden`, §1) → read that slot's flags and normalised serial → `PinLocked` if `CKF_USER_PIN_LOCKED`; `PinRateLimited` if the limiter for that serial is locked out → set `final_try` if `CKF_USER_PIN_FINAL_TRY` (the child then shows "This is the LAST PIN attempt before the token locks." and requires a tick-box before OK) → `host.run_dialog` → `sign_pdf(selected, certificates, ...)`.
- **Single login on the chosen token.** Exactly one `C_Login` per PIN entry, on the slot whose freshly read `getTokenInfo().serialNumber`, normalised with `_token_field`, equals `selected.token_serial`. Re-read immediately before login. The slot is `selected.slot_id` when its freshly read serial matches; otherwise (serial differs, or empty, or `selected.slot_id` no longer holds that serial) → `TokenUnavailable` ("The USB token is not available. Check that it is plugged in and try again."), NO login. Never loop over slots with a PIN.
- **Limiter** (on `SignerService`, in memory, keyed by `token_serial`): counts consecutive failed logins reported as `CKR_PIN_INCORRECT`, `CKR_PIN_INVALID` or `CKR_PIN_LEN_RANGE` (middleware differs; other codes such as GENERAL_ERROR, TOKEN_NOT_PRESENT, SESSION_*, USER_ALREADY_LOGGED_IN, DEVICE_REMOVED are NOT counted); after `MAX_PIN_FAILURES` the token is refused for `PIN_LOCKOUT_SECONDS` measured from the LAST failure (each further failure re-arms it); success (`C_Login` OK) clears. The per-serial TOKEN lock (`acquire(timeout=TOKEN_LOCK_TIMEOUT_SECONDS=20)`, a `service.py` constant; on timeout `TokenBusy`, code `TOKEN_BUSY`, 429) is taken BEFORE the token flags are read and held through: flags read → locked/limiter checks → dialog → login → sign → TSA → close/logout, so one request cannot change the token's state (FINAL_TRY, locked) between another request's check and its login (found by adversarial review: two concurrent wrong PINs previously locked the token). Under the guard, immediately before `C_Login`, the flags are RE-READ: locked ⇒ `PinLocked`, FINAL_TRY newly set but the dialog was not shown with `final_try` ⇒ `TokenBusy` ("state changed"), no `C_Login` in either case; the limiter is re-checked there too. A daemon restart resets it (I7). While a request is in its PIN dialog, another request for the same token is refused at once with `TokenBusy`; a request that was waiting when such a dialog opened, or whose origin was unpaired while it waited, is refused once it gets the lock, with no dialog (pairing is re-checked after the lock wait). The TSA request is bounded by `token.TSA_TIMEOUT_SECONDS=15` (connect `TSA_CONNECT_TIMEOUT_SECONDS=5`), passed to endesive via `timestamp_req_options`; a TSA failure is `TOKEN_SIGNING_FAILED` after logout (read timeouts apply per socket read; DNS is not covered — residual).
- **Errors on the login/sign path** (`session.login` through `sign`): no driver/Tk text interpolated. `CKR_PIN_INCORRECT` → `PinIncorrect` (`PIN_INCORRECT`, 401, "The PIN was incorrect. Check the remaining attempts before trying again."); `CKR_PIN_LOCKED` → `PinLocked` (`PIN_LOCKED`, 423, "The token is locked. Unlock it with your DSC provider's tool."); `PinRateLimited` (`PIN_RATE_LIMITED`, 429, "Too many incorrect PINs were entered for this token. Wait a few minutes."); other → `TOKEN_SIGNING_FAILED` ("The USB token could not sign the document."). Pre-login messages (module load, enumeration) name the module label and, for a driver failure, only the PKCS#11 return-code NAME (from the daemon's own `PyKCS11.CKR` table, else "driver error"); since the probe child below they never carry driver exception text or a path.
- **PIN-free reads in a child (2026-11-10).** The WatchData library hung inside `C_GetSlotList` after a token swap; the daemon thread never returned and `/v1/health` stopped answering. `TokenClient.certificates()` and `token_state()` therefore never load the vendor library in the daemon: `token.run_probe` starts `token_probe.py` as `[sys.executable, "-I", <file>]` (own session, cwd "/", `ui.child_env` allowlist, stderr discarded) and sends ONE JSON request on stdin (`op`, the module path the ProviderRegistry resolved — never one from the HTTP request — and an `alarm`). The child reports public data only (slot ids, raw token label/serial, flags, certificate DER / CKA_ID / CKA_LABEL as base64, return codes as numbers) in ONE line of at most `token_probe.MAX_REPLY_BYTES` (256 KiB). The daemon refuses duplicate keys, NaN, unknown fields, non-ASCII, a second line or oversize, and after `token.PROBE_TIMEOUT_SECONDS` (15 s) of wall clock it SIGKILLs the child's whole process group and reaps it; the child also arms SIGALRM (default action) so it dies if the daemon does. Every such failure is `TokenDriverNotResponding` (`TOKEN_UNAVAILABLE`, 409, "The token driver is not responding. Unplug and re-insert the token, then try again."), raised outside any `except`, plus one stderr line with `op` and `reason` from closed vocabularies. Outcomes are unchanged: `CertificatesHidden` only for a clean empty listing, one unreadable slot never hides another's certificates, `token_state` still requires `selected.slot_id` to be the only slot with `selected.token_serial`. Residual: the sign path (`_TokenHSM`: slot re-read, `C_Login`, `C_Sign`) still runs in the daemon, which now first loads the library there lazily; a hang there is not bounded yet (phase 2).
- **Listing across every installed driver (2026-11-10).** With two drivers installed (WatchData plus a configured InnaitKey module), "auto" used to fail with `MODULE_SELECTION_REQUIRED` and the Desk had no way to pick a module. `/v1/certificates` (`SignerService.list_certificates`) now takes `ProviderRegistry.candidates(provider, module_id)`: one candidate is read exactly as before (its errors propagate); several (auto, or a provider with several installed modules, no `module_id`) are ALL read, each through its own killable probe, in daemon threads, under `service.CERTIFICATE_LISTING_SECONDS` (20 s) in all; a module with no token, a hung driver or any other failure is skipped. If none could be read: `CertificatesHidden` when one reported it, else `TokenUnavailable` with its fixed default text (no driver text, no path). Only signing certificates are listed (`certificates.is_signing_certificate`, from the parsed certificate: not a CA, not self-issued, KeyUsage digitalSignature or nonRepudiation — a certificate without KeyUsage is not listed); the same certificate on the same token through a second module is listed once, from the first module in registry order. Each entry gains `module_id` and `provider` from the registry, and the metadata gains `organization` (subject O, control/format characters removed, capped at 256, "" if absent). `/v1/sign` is unchanged and stays explicit: the Desk sends the listed `module_id` and `provider`; several matching modules without a `module_id` is still `MODULE_SELECTION_REQUIRED`, and a `module_id` is only ever compared with registry ids, never used as a path. The Desk picker shows each certificate in plain words (who signs and for which company, type, validity and issuer, token label; never a fingerprint), escaped, with a display-only hint comparing the certificate's organisation with the invoice company, and asks for confirmation even when there is only one certificate. Tests: `local_signer/tests/test_certificate_listing.py`, `test_certificate_der.py::TestOrganizationMetadata`, `erp_dsc_signer/tests/test_signing_authenticate.py::TestSalesInvoiceJsContract`.
- **Certificate form and dependencies.** `_TokenHSM.certificate()` returns the token certificate as DER bytes (endesive 2.19.3 loads it with asn1crypto from bytes; a cryptography object raises `TypeError`, which made every real USB signing fail as `TOKEN_SIGNING_FAILED`); `othercerts` stay cryptography objects (endesive calls `public_bytes` on each). `local_signer/pyproject.toml` declares `attrs>=22` and `cryptography>=42` (endesive imports `attr` and `cryptography.x509.verification` without declaring them). A real-endesive end-to-end test with a software key proves it.
- **`signature_meta` allowlist (security).** The signer never forwards the website's `signature_meta` to endesive as received: `service.sanitise_signature_meta` runs FIRST in `sign` (before token selection, the lock or any dialog) and accepts only the keys the ERP really sends (`aligned, sigflags, sigflagsft, sigpage, sigbutton, sigfield, auto_sigfield, sigandcertify, signaturebox, name, contact, location, signingdate, reason, application, signature_appearance{display, outline, border}`), type- and size-checked with the claim character rule; `signature_appearance.icon` (a server-local path) is DROPPED, not an error; any other or unknown key or wrong type is refused with the fixed message "The signing request contains an unsupported field." that never names the key or value. Every listed key is REQUIRED (an empty or partial `signature_meta` is refused), and the constants the ERP always sends are pinned: `aligned` 32768, `sigflags` 3, `sigflagsft` 132, `sigandcertify` false (true would turn the approval signature into a DocMDP certification), `auto_sigfield` true, `application` "ERPNext"; `sigfield` may not contain "."; `sigbutton` is accepted but inert (endesive 2.19.3 never reads it). `signature_appearance.display` is written raw into the appearance content stream after a UTF-16BE→latin-1 conversion, so any character above U+FFFF or having 0x28, 0x29 or 0x5C as either UTF-16BE byte is refused (this also refuses a few Devanagari letters such as U+0928, whose appearance would be corrupt anyway). A `signature_meta` that is not a JSON object gets the same fixed message. Verified against the real ERP `_signature_metadata` output. This closes: embedding local image files (`signature_img`, `background`, `icon`), fonts (`manual_fonts`) and network calls (`ltv`) requested by a paired site.
- **SHA-256 only.** `_TokenHSM.sign` signs with `CKM_SHA256_RSA_PKCS` only, never a mechanism derived from endesive's argument; any digest other than exactly "sha256" (endesive takes it from the PDF's own `/Perms /DocMDP /Reference[0] /DigestMethod`) is refused before `C_Login`, so no PIN is sent, as `TOKEN_SIGNING_FAILED` stage `c_sign`. A token that supports only plain `CKM_RSA_PKCS` is NOT supported (no fallback with a SHA-256 DigestInfo prefix is built); the diagnostic would show `CKR_MECHANISM_INVALID`. The Watchdata ProxKey token lists `CKM_SHA256_RSA_PKCS`.
- **Operator diagnostic.** `TOKEN_SIGNING_FAILED` keeps its one fixed message and gains `details = {stage, error, ckr}` from CLOSED vocabularies only: `stage` in {login, find_key, c_sign, cms, tsa, other}; `error` an exception CLASS NAME from an allowlist (else `other`), never `str`/`repr`/args/traceback; `ckr` a PKCS#11 name matching `CKR_[A-Z0-9_]+` looked up from the return code, else null; the error-class allowlist includes `AssertionError` (signature larger than `aligned`) and `IndexError` (`sigpage` past the last page); `tsa` is a requests exception or, when a `timestamp_url` is set, any other non-`LocalSignerError` raised after a `C_Sign` has returned (a TSA that answers but refuses yields a plain `ValueError`). One fixed line with the same three fields goes to stderr. No text that could contain a PIN can enter it.
- **PIN references.** `_TokenHSM` sets `pin = None` as soon as `C_Login` returns or raises; `sign_pdf`'s `finally` does so too for paths that never reach `C_Login`; `service.sign` never binds the PIN to a local and passes the dialog's return value straight into `sign_pdf`. PyKCS11's `login()` copies the PIN into its own byte list, which cannot be wiped (I7). Python `str` cannot be zeroed (I7).

## 8. Daemon output
`handle_error` on the `make_server()` subclass logs one fixed line, no traceback. `do_GET`/`do_POST` catch `Exception`; `_error` swallows `BrokenPipeError`.

## 9. Child UI contract
Origin in its own label, always first: the scheme on its own line and the HOST (with any port) on ONE unbroken line that is never wrapped, split, elided or altered (a wrapped host lets an attacker subdomain such as `erp.mycompany.com.evil.example` show the victim's host alone on line 1; the window grows instead); `warnings` as the signer's own text; claims one per line, each on ONE unwrapped line prefixed "as described by the site:" (so site text can never start a line without the prefix). PIN: masked; the Entry is DISABLED until the user clicks inside the dialog, and the click that enables it and Return/OK are ignored for `INPUT_GUARD_SECONDS` after the window maps and after focus RETURNS from outside (focus was inside, left, came back; the first activation of an initially unfocused window does not re-arm it, so the first deliberate click works), with the hint "Wait..." while armed and "Click inside this window again, then type your PIN." after an ignored click (a click already in flight when the always-on-top window appears must not enable the Entry and submit the keystrokes meant for another window) (so no keystroke is dropped or typed into another window by the dialog's own behaviour); `sales_invoice.js:64` freeze text becomes "Click the signer window, then type your PIN". Consent: Allow/Deny disabled for `INPUT_GUARD_SECONDS` after the window maps and after focus returns from outside; Deny has initial focus; Tab order Deny→Allow; Allow only by click or Space on the focused Allow button; no Tk `default=` on Allow; Escape and window close are ALWAYS a Deny, including during the input guard (a refusal is the fail-closed direction and the BRD requires it unconditionally; the input guard disables only the Allow and Deny BUTTONS, never Escape/close). Residual: a stray Escape within the first 1.5 s stores a 24-hour denial (`trust.py:42`); the user can re-pair later, and this is availability-only; the child's own timeout is the `timeout` result. All strings go to Tk as `text=`/`textvariable`; no `tk.eval`. Fail closed on layout: if even the minimum font cannot show the whole host within the screen width, the child answers `deny` (consent) or `cancelled` (PIN) without drawing any Allow/OK, and claims are never drawn in a larger font than the origin. Residual: the Tk Entry is not a macOS secure text field; a background daemon cannot force focus on current macOS (hence click-first).

## 10. Invariants, tests, gates
- **I1** PIN: keystrokes → child memory → stdout pipe → daemon memory → one `C_Login` on the chosen token. Never argv, env, file, log, socket, HTTP body or ERP request.
- **I2** No echo: stderr discarded; fixed error text; `from None`; reply parsed outside `except`; core dumps off in parent and child.
- **I3** ERP never receives or stores a USB PIN. **I4** Site-controlled data only as validated separate fields on stdin. **I5** One child, tracked, killed/reaped on deadline, shutdown, SIGTERM; child exits when the parent dies; an un-reapable child keeps the lock. **I6** Fail closed per §6.
- **I7 (declarative)** In scope: malicious/compromised ERP site, page script, network attacker, other OS users, files/logs/backups. Out of scope and UNATTAINABLE in software: a same-user process with debug/Accessibility rights, or root. "Never stored/logged/sent" is a guarantee about persistence and transmission by this tool and the ERP site, not against OS swap/hibernation/crash reporters or a compromised workstation. The PIN sits in daemon memory, the pipe buffer and the parse buffer for one signing call; dropping references removes ours only. If the user types before the dialog has focus the keys go to the focused window (the ERP page is in scope as an attacker); click-first and the Desk text mitigate it; a hardware PIN-pad token removes it (not implemented). The limiter state is lost on daemon restart. A paired site can re-prompt repeatedly; the remedy is `erp-dsc-local --revoke <origin>`.
