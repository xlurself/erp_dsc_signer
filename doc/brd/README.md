# BRD folder — numbering convention

- `000-INDEX.md` — the master index (serial-numbered table of every feature).
- `NNN-slug.md` — one file per feature, e.g. `001-user-login.md`, `002-checkout.md`.
  - `NNN` is a zero-padded serial (priority-ordered; lower = higher priority).
  - `slug` is a short kebab-case name.
- `brd.json` — the MACHINE-READABLE contract the server reads. **GENERATED by `POST /api/brd/approve` from the markdown above — never hand-edit it, and do not create it yourself.** Until you approve, the file is simply absent and review-injection stays inert. If approval returns 400 it names the file and field to fix; fix the **markdown**, not the JSON.

## Per-feature file front-matter
Start each `NNN-slug.md` with a small front-matter block the tracker reads:

```
---
id: F1
title: User login
priority: P0
status: planned
covers: [F1]
---

## Summary
...

## Done when
- POST /login with valid creds → 200 + session cookie
- Invalid creds → 401
```

The founder approves; the developer authors. The server never writes these files after first scaffold.
